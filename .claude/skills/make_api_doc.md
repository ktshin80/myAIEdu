# /make_api_doc

백엔드 코드를 읽어 `API.md`를 생성·갱신한다. 문서의 모든 내용은 **코드에서 읽은 사실**만 쓴다. 추측하거나 기억에 의존하지 않는다. 코드와 문서가 다르면 코드가 맞다.

## 입력과 출력

- 인자 없음: 모든 API를 다시 분석해 `API.md` 전체를 만든다.
- 인자 있음(예: `/api/enroll`): 그 경로의 섹션만 갱신하고 나머지는 그대로 둔다. 코드에 없는 경로면 만들지 않고 알린다.
- 출력 파일: 프로젝트 루트의 `API.md` (UTF-8, 한국어). 새 폴더를 만들지 않는다(`architecture.md` 1장).
- 소스 코드, `data/academy.db`, `.claude/rules/`는 수정하지 않는다. 수정 대상은 `API.md`뿐이다.

## 분석 절차

아래 순서대로 읽는다. 각 단계에서 얻은 사실이 템플릿의 어느 칸에 들어가는지 함께 적었다.

1. **엔드포인트 수집** - `src/back/main.py`의 `build_router`에서 `router.include(...)`로 등록된 라우터를 찾는다. 등록되지 않은 라우터 파일은 문서화하지 않는다(활성화되지 않은 API). 이어서 `src/back/routers/*_router.py`의 `build_routes`에서 `Route("메서드", "경로", 핸들러)`를 모두 뽑는다. → 메서드, 경로
2. **핸들러 읽기** - 핸들러 함수에서 다음을 확인한다.
   - 쿼리 파라미터: `request.param("이름")` → 이름, 선택 여부
   - 요청 본문: `request.json()`을 어떤 모델의 `from_payload`로 넘기는지 → 요청 모델
   - 응답: `Response(상태코드, 본문)`의 상태 코드와 본문 모양(`asdict` 결과인지, `message`를 담은 dict인지)
3. **요청 모델 읽기** - `src/back/models/`의 해당 `from_payload`에서 필드별 타입, 필수 여부, 정규화(`strip`, `lower`), 검증 조건과 `ValidationError` 메시지를 옮긴다. 허용 값 목록(예: `PERSONAS`)은 상수 정의를 열어 실제 값을 적는다. → 요청 필드 표, 400 오류
4. **응답 모델 읽기** - `asdict`로 내보내는 dataclass의 필드 이름과 타입을 읽는다. → 응답 필드 표, 응답 예시
5. **업무 오류 수집** - 핸들러가 부르는 서비스 메서드를 따라 `services/`에서 `raise`되는 예외를 모두 찾고, 필요하면 `repositories/`에서 `sqlite3` 예외를 바꿔 올리는 곳도 확인한다. 각 예외의 `status`와 메시지는 `src/back/errors.py`의 클래스 정의에서 가져온다(메시지를 직접 지어내지 않는다). → 오류 표
6. **조회 파라미터의 서비스 동작** - 쿼리 값이 서비스에서 어떻게 쓰이는지(허용 값, 기본값, 잘못된 값일 때 동작)를 확인한다. 코드가 말해 주지 않는 부분은 "코드에서 확인되지 않음"이라고 쓴다.
7. **응답 예시 작성** - 위에서 읽은 필드로 JSON 예시를 만든다. 이름, 이메일, 전화번호는 반드시 가짜 값(`홍길동`, `hong@example.com`, `010-0000-0000`)을 쓴다. 실제 DB를 읽어 예시를 만들지 않는다.
8. **문서 작성과 검증** - 아래 템플릿으로 `API.md`를 쓴 뒤 다음을 확인한다.
   - 1단계에서 찾은 경로 수와 문서의 엔드포인트 수가 같다.
   - 모든 오류 표 행의 상태 코드와 메시지가 `errors.py`나 모델의 문자열과 글자 그대로 같다.
   - 오류 응답은 전부 `{"error": "..."}` 형식이고, 성공 응답에 `error` 키가 없다.

## 문서화 규칙

- 상태 코드 기준은 `architecture.md`를 따른다: 조회 200, 생성 201, 형식 오류 400, 없음 404, 충돌 409, 서버 오류 500.
- 코드와 규칙이 어긋나면(예: 규칙은 201인데 코드는 200) 코드대로 적고 문서 끝 `확인 필요` 절에 따로 모은다. 코드를 고치지 않는다.
- 500 오류는 엔드포인트마다 반복하지 않고 문서 앞부분 "공통" 절에 한 번만 쓴다.
- 날짜, 정원, 수강료처럼 아직 정해지지 않은 값은 값을 만들어 내지 않는다.
- 전체 갱신 시 문서 맨 위의 `기준 시각`을 오늘 날짜로 바꾼다.

## 템플릿

`API.md`는 아래 양식을 그대로 따른다. `<...>`는 분석 결과로 채우고, 해당 없는 칸은 줄째 지우지 말고 `없음`이라고 쓴다.

````markdown
# myAIEdu API 명세

> 이 문서는 `/make_api_doc`이 `src/back/routers/`를 분석해 만든 것이다. 직접 고치지 말고 코드를 바꾼 뒤 다시 생성한다.
> 기준 시각: <YYYY-MM-DD>

## 공통

- 기본 주소: `http://127.0.0.1:8000`
- 요청·응답 본문: `application/json`, UTF-8
- 오류 응답은 항상 아래 형식이다.

```json
{ "error": "한국어 오류 메시지" }
```

- 예상하지 못한 서버 오류는 `500`과 일반 안내 문구로 응답하며, 내부 정보는 담지 않는다.

## 목록

| 메서드 | 경로 | 설명 | 성공 코드 |
|--------|------|------|-----------|
| <GET> | `<경로>` | <한 줄 설명> | <200> |

---

## <메서드> `<경로>`

<이 API가 무엇을 하는지 한두 문장. 업무 규칙(중복 거절, 정원 제한 등)이 있으면 여기에 쓴다.>

### 요청

**쿼리 파라미터** (없으면 `없음`)

| 이름 | 타입 | 필수 | 설명 |
|------|------|------|------|
| `<track>` | string | <아니오> | <허용 값과 생략 시 동작> |

**본문** (없으면 `없음`)

| 필드 | 타입 | 필수 | 설명 |
|------|------|------|------|
| `<name>` | string | 예 | <정규화 방식, 제약> |

### 응답

**<200 OK>**

```json
<가짜 값으로 만든 예시>
```

| 필드 | 타입 | 설명 |
|------|------|------|
| `<id>` | integer | <의미> |

### 오류

| 상태 | 조건 | 메시지 |
|------|------|--------|
| <400> | <어떤 입력일 때> | `<errors.py 또는 모델의 문구 그대로>` |

## 확인 필요

- <코드와 규칙이 다른 점, 코드에서 확인되지 않은 동작. 없으면 `없음`>
````

## 마무리 보고

- 읽기만 했고 서버를 실행하거나 DB를 건드리지 않았다는 점
