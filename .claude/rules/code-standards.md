# myAIEdu 코딩 표준 (전역 규칙)

이 프로젝트를 여는 모든 팀원과 Claude에게 공통으로 적용되는 코딩 규칙이다. 판단 기준은 테크 리드의 "실무 밸런스형" 원칙, 즉 계층은 분리하되 과한 추상화는 하지 않는 것이다. 구조와 계층 규칙은 `architecture.md`를 따르고, 이 문서는 그 위에 얹는 전역 코딩 룰이다.

## 1. 주석은 한국어로 작성한다

- 코드에 다는 주석과 docstring은 모두 한국어로 쓴다. (팀 합의: "한국어로 주석처리 해줘")
- 범위는 Python, JavaScript, CSS, HTML, SQL을 가리지 않는다.
- 코드만 봐서는 알 수 없는 이유(왜)를 적는다. 코드가 하는 일을 그대로 되풀이하지 않는다.
  - 좋은 예: `# 같은 이메일은 한 명의 수강생으로 보므로 먼저 조회한다`
  - 나쁜 예: `# 이메일로 조회한다`
- 새 코드를 쓰거나 기존 코드를 고칠 때, 영어로 된 주석을 발견하면 같은 변경 안에서 한국어로 바꾼다. 건드리지 않은 파일까지 일괄 번역하지는 않는다.
- 사용되지 않는 코드를 주석으로 남겨 두지 않는다. 지운다.
- 외부 표준이나 라이브러리가 요구하는 영어 고정 문자열(HTTP 헤더, MIME 타입, SQL 키워드)은 그대로 둔다.

## 2. 언어 규칙

- 사용자에게 보이는 모든 문구(화면, 오류 메시지, 로그 안내)는 한국어다.
- 식별자(변수, 함수, 클래스, 파일명)는 영어다. Python은 `snake_case`/`PascalCase`, JS는 `camelCase`/`PascalCase`를 쓴다.
- 파일 인코딩은 UTF-8이고 JSON 출력은 `ensure_ascii=False`다.

## 3. 작성 원칙

- 표준 라이브러리만 쓴다. 새 패키지가 필요해 보이면 구현 전에 먼저 묻는다.
- 요청한 범위만 구현한다. 만약을 위한 추상화, 미사용 코드, 범위를 넘는 리팩토링을 하지 않는다.
- 외부 입력은 신뢰하지 않고 모델에서 검증한 뒤 서비스로 넘긴다.
- 개인정보(이름, 이메일, 전화번호)를 로그나 오류 메시지에 남기지 않는다.
- 프론트엔드는 외부 문자열을 `textContent`로만 화면에 넣는다. 대상 사용자가 4050이므로 접근성(`label`, 충분한 글자 크기)을 유지한다.

## 4. 변경 후 확인

- 코드를 바꾼 뒤 `python -m compileall -q src server.py`로 문법을 확인한다.
- 확인하지 못한 것은 보고할 때 명시한다.
